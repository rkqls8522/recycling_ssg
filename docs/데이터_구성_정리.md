목표는 "장수를 맞추는 것"이 아니라 **"정보량을 맞추는 것"** 이었습니다.

## 3. 대응 ② — 적은 쪽은 직접 수집한다 (신문지)

신문지 136장은 어떤 샘플링으로도 해결되지 않아 **웹 크롤링**으로 보강했습니다.

### 대응 ③ — 크롤링 데이터는 전수 검토 후 선별

크롤링 결과에는 신문지와 무관한 사진이 많이 섞여 있어 사람이 직접 확인해
쓸 만한 것만 남겼습니다. 파일 번호의 결번으로 확인됩니다.

| | 번호 범위 | 채택 | 채택률 |
| --- | --- | --- | --- |
| clean | 0001 ~ 0435 | 250장 | **57%** |
| damaged | 0479 ~ 0568 | 88장 | 98% |

**clean 은 절반 가까이를 버렸습니다.** 검수를 건너뛰었다면 노이즈를 학습시킬 뻔했습니다.

### 대응 ④ — 그래도 부족한 만큼 오프라인 증강

```
AI Hub 원본       104장   (clean 59 + damaged 45)
크롤링 채택       +338장   (clean 250 + damaged 88)
   ↓
고유 원본          442장   ← 서로 다른 장면 수
   ↓
오프라인 증강    +1,294장   원본 1장당 3장 (aug0 / aug325 / aug650)
   ↓
최종 학습        1,736장   전체의 1.20%
   ↓
검증 세트           16장   ← 전체 10,548장 중 0.15%
```

전처리 필터에서 **제외 0건** — 17개 클래스 중 유일하게 전량 통과했습니다.
크롤링 검수가 제대로 됐다는 방증입니다(SHA-1 중복도 0건).

## 4. 대응 ⑤ — train/val 간 부족분 상호 보충

train 이 부족하고 val 에 여유가 있으면 val 일부를 train 으로 돌렸고, 반대도 했습니다.
`build_report.txt` 의 `val_fill` 항목이 그 기록입니다.

```
비닐     clean  10,000 (real 7,763 + val_fill 2,237)
유리병   damaged 2,000 (real   340 + val_fill 1,660)
의류     damaged 2,000 (real   204 + val_fill 1,796)
```

누수 방지를 위해 전처리에서 **SHA-1 교차 검사**를 돌렸고,
실제로 **10건**이 걸려 val 쪽을 제거했습니다.

## 7. 검증 — 불균형 해소만으로는 부족했습니다

학습량과 성능의 순위상관을 계산했습니다.

```
스피어만 순위상관 (17개 클래스)
  전체        : +0.164
  신문지 제외  : -0.003   ← 사실상 무상관
```

약한 상관마저 신문지 하나가 만든 것이고, 나머지 16개에서는 데이터 양이
성능을 전혀 설명하지 못했습니다.

성능이 낮은 클래스는 **원인이 두 갈래**이고 처방이 정반대입니다.

### 유형 ① 다양성 부족 → 추가 수집

| 클래스 | 고유 원본 | mAP |
| --- | --- | --- |
| 신문지 | 442 | 0.4396 |
| 종이 | 1,577 | 0.7094 |

증강으로는 장수만 늘 뿐 고유 장면은 그대로라 해결되지 않습니다.

### 유형 ② 클래스 간 혼동 → 클래스 병합 또는 평가 기준 변경

| 클래스 | 고유 원본 | mAP |
| --- | --- | --- |
| 고철류/비철금속 | 6,190 | 0.6855 |
| 고철류/고철 | 10,924 | 0.7753 |

**데이터가 충분한데도 낮습니다.** 혼동 행렬상 서로를 헷갈립니다.

```
고철   → 고철 0.69 / 비철금속 0.20
비철금속 → 비철금속 0.61 / 고철 0.28
```

더 모아도 풀리지 않습니다. 다만 둘 다 대분류가 '고철류'로 같아 배출 방법이
동일하므로 **서비스상 오답은 아닙니다.** 대분류 기준으로는 둘 다 약 0.89 입니다.

## 8. 전처리에서 제외된 9,762건

| 사유 | 건수 | 성격 |
| --- | --- | --- |
| `invalid_bbox` | 6,086 | bbox 가 이미지 밖으로 10% 이상 벗어남 (원본 라벨 품질) |
| `within_split_exact_duplicate` | 3,666 | 같은 split 안의 SHA-1 완전 중복 |
| `cross_split_exact_duplicate` | 10 | train/val 누수 → val 쪽 제거 |

클래스별 성격이 다릅니다.

- **종이류/종이 3,495건** — 대부분 중복(3,381). 증강본을 채우는 과정에서 생김
- **고철 1,174 / 플라스틱 1,077 / 캔 893** — 대부분 `invalid_bbox`
- **신문지 0건** — 유일하게 전량 통과

`invalid_bbox` 가 6,086건이라는 건 **원본 라벨 품질이 균일하지 않다**는 뜻이며,
특히 형태가 불규칙한 금속·플라스틱에 몰려 있었습니다.

## 9. 정직하게 밝힐 한계

**신문지 검증 세트가 16장입니다.** mAP 0.4396 은 16장으로 측정한 값이라
신뢰구간이 매우 넓습니다. 학습뿐 아니라 평가도 신뢰하기 어렵습니다.

**신문지 val 에는 크롤링 이미지가 없습니다.** 학습 데이터의 76%가 크롤링본인데
검증은 AI Hub 원본 16장으로만 했습니다. 학습·평가 분포가 어긋난 설계 실수입니다.

**SHA-1 은 완전 중복만 잡습니다.** 같은 물건을 연속 촬영한 유사 이미지는
걸러내지 못하므로, 실제 고유 다양성은 128,471장보다 낮을 수 있습니다.

**형태 다양성 판단이 정성적이었습니다.** "스티로폼은 일관되고 고철은 다양하다"는
눈으로 본 판단이었습니다. 색상 히스토그램 분산이나 임베딩 클러스터 수 같은
정량 지표로 뒷받침했다면 더 설득력이 있었을 겁니다.
