# A. 실험 신뢰성 — 가장 날카로운 질문들

### Q1. 증강 효과 +0.0243 인데, seed 노이즈가 0.0085면 그 차이가 의미 있나요?

**가장 중요한 질문입니다. 정직하게 답하면 "단일 측정으로는 의미 없다" 입니다.**

실제로 05번에서 같은 설정을 seed만 바꿔 3번 돌렸을 때:

```
trial 1 : 0.8379 / 0.8472 / 0.8247   → 범위 0.0226
trial 2 : 0.8316 / 0.8484 / 0.8423   → 범위 0.0168
```

증강 효과 +0.0243은 이 노이즈와 비슷한 크기입니다.

그래서 저희는 **크기가 아니라 일관성**으로 판단했습니다.

- 증강 효과: **18번 측정 중 17번 양수** (예외는 motion blur 하나)
- 하이퍼파라미터 효과: **6번 측정 중 6번 음수**

노이즈라면 부호가 반반씩 나와야 합니다. 한쪽으로 몰린 건 실제 효과가 있다는
뜻입니다. 이항검정으로 보면 17/18이 우연일 확률은 0.1% 미만입니다.

**다만 "mosaic이 Y14보다 정확히 얼마나 좋은가"(+0.0415 vs +0.0367) 같은 세부
순위는 노이즈 범위 안이라 주장하지 않습니다.** 저희가 말할 수 있는 건
"mosaic 계열이 다른 증강보다 낫다" 까지입니다.

### Q2. seed를 1개만 쓴 실험이 대부분인데 재현성이 있나요?

seed 42 고정에 `deterministic=True` 로 재현 가능하게 했지만, **다른 seed에서
같은 값이 나온다는 뜻은 아닙니다.**

3-seed 검증은 비용 때문에 05번의 상위 후보 3개에만 적용했습니다
(3 trial × 3 seed × 10 epoch). 전체 82런에 적용했다면 3배의 시간이 필요했습니다.

대신 **같은 결론이 서로 다른 데이터셋(05 / 06-1 / 06-2)에서 반복되는지**로
검증했습니다. 세 노트북 모두에서 mosaic이 1위, auto가 튜닝값보다 우세했습니다.
seed 반복 대신 조건 반복을 쓴 셈입니다.

### Q3. 최종 조합(mosaic + auto)을 직접 실험하지 않고 정했다는 게 위험하지 않나요?

맞습니다. 위험한 선택이었고, 그래서 근거를 따로 쌓았습니다.

2×2 설계로 증강과 하이퍼파라미터를 **분리해서** 측정했습니다.

| | 증강 OFF | 증강 ON |
| --- | --- | --- |
| optimizer auto | B00 | B01 |
| Optuna 튜닝 | B03 | B02 |

두 요인 모두 방향이 일관됐기 때문에(17/18, 0/6) 조합해도 된다고 판단했습니다.
만약 한쪽이라도 엇갈렸다면 직접 측정한 조합을 썼을 겁니다.

**결과적으로 최종 학습에서 0.8638이 나와 예상 범위 안이었습니다.**
06번 최고 기록(0.8424, 같은 조건 아님)보다 높았고, 요인 분해가 옳았다는
사후 증거가 됐습니다.

### Q4. 노트북마다 mAP를 비교하는데, 검증 세트가 다르지 않나요?

**다릅니다. 그래서 노트북 간 mAP는 직접 비교하지 않습니다.**

| 노트북 | 검증 장수 |
| --- | --- |
| 02 / 04 / 05 / 06-1 | 2,201 |
| 06-2 | 2,200 |
| **07** | **10,548** |

저희가 결론을 낼 때 쓴 건 **각 노트북 안에서의 차이(Δ)** 뿐입니다.
"05번의 Y08이 05번의 B00보다 +0.019" 같은 식으로요. 그 Δ들을 모아 평균 낸 것이
증강 효과 집계입니다.

중간 실험 04번의 0.8670이 최종 07번의 0.8638보다 높은 것도 같은 이유로
**비교 불가**입니다. 07번이 4.8배 큰 검증 세트에서 낸 값이라 추정이 더 안정적입니다.

### Q5. Train/Validation 데이터 누수는 확인했나요?

했습니다. 전처리에서 모든 이미지의 **SHA-1 해시**를 계산해 교차 검사했습니다.

```
후보 164,625장 중 9,762건 제외 -> 154,863장 사용
  invalid_bbox                      6,086   bbox가 이미지 밖으로 10% 이상 벗어남
  within_split_exact_duplicate      3,666   같은 split 안의 완전 중복
  cross_split_exact_duplicate          10   train/val 간 중복 -> val에서 제거
```

train과 val에 동일한 이미지가 10건 있었고 val 쪽을 제거했습니다.

다만 **해시가 다른 유사 이미지(같은 물건을 연속 촬영한 것)는 걸러내지 못합니다.**
원본 데이터셋의 Training/Validation 분할을 그대로 따랐으므로 그 분할을 신뢰한 셈입니다.
이건 한계로 인정합니다.

# B. 결과 해석과 약점

### Q6. 신문지 성능이 0.4396으로 유독 낮은데 왜 그런가요?

**저희 판단 착오일 가능성이 큽니다.** 혼동 행렬을 보면 원인이 드러납니다.

```
신문지의 실제 예측 분포
  0.48  신문지로 정답
  0.24  비닐로 오인
  0.24  아예 검출 못 함 (background)
```

두 가지가 겹쳤습니다.

**첫째, 구겨진 신문지가 비닐봉투와 시각적으로 유사합니다.** 24%가 비닐로 갔습니다.

**둘째, 저희가 신문지를 학습 중 증강에서 제외했습니다.** "이미 오프라인에서
4배 증강했으니 추가 증강은 과증강"이라고 판단했는데, 06-1 실험을 다시 보면
신문지는 **증강 효과를 가장 크게 받는 클래스**였습니다.

```
06-1 신문지 성능
  증강 OFF  : 0.4136
  mosaic ON : 0.7680
07 최종 (증강 제외) : 0.4396   ← 증강 OFF 쪽 수치에 가깝습니다
```

신문지가 0.77 수준이었다면 전체 mAP도 **0.8638 → 0.8832 (+0.019)** 였을 것으로
추산합니다. 다음 학습에서 `EXCLUDE_NEWSPAPER_FROM_AUG = False` 로 재검증할 계획이고,
설정 한 줄만 바꾸면 되도록 만들어 뒀습니다.

### Q7. 고철과 비철금속도 0.69 / 0.61로 낮습니다. 문제 아닌가요?

**모델의 한계는 맞지만, 서비스 영향은 거의 없습니다.**

혼동 행렬을 보면 둘은 **서로를** 헷갈립니다.

```
고철   → 고철 0.69 / 비철금속 0.20
비철금속 → 비철금속 0.61 / 고철 0.28
```

그런데 **둘 다 대분류가 '고철류'로 같습니다.** 사용자에게 주는 답이 동일하므로
서비스 관점에서는 오답이 아닙니다. **대분류 기준으로 다시 계산하면 둘 다 약 0.89입니다.**

종이류도 마찬가지입니다. 종이(0.61)가 박스류(0.11)나 책(0.05)으로 가는 건
같은 대분류 안의 혼동입니다.

**반면 신문지가 비닐로 가는 건 대분류가 달라 진짜 오류입니다.** 그래서 신문지만
따로 문제로 봅니다.

솔직히 말하면, 평가지표를 17개 소분류가 아니라 **12개 대분류 기준으로도 함께
보고했어야 했습니다.** 그게 서비스 성능에 더 가까운 숫자입니다.

### Q8. 어느 클래스를 가장 못 맞추나요? 실패 사례가 있나요?

낮은 순서대로 신문지(0.44), 비철금속(0.69), 종이(0.71), 고철(0.78) 입니다.
나머지 13개는 모두 0.89 이상입니다.

공통점은 **재질이 비슷하고 형태가 일정하지 않은 것**들입니다.
구겨진 종이, 찌그러진 금속처럼 모양이 고정되지 않은 물체가 어렵습니다.

반대로 잘 맞추는 건 의류(0.98), 책(0.98), 스티로폼(0.97) 처럼
**형태와 질감이 뚜렷한** 것들입니다.

### Q11. 클래스 불균형은 어떻게 해결했나요?

#### 출발점

원본 데이터는 클래스 간 차이가 **349배** 였습니다.
유리병 47,411장, 신문지 136장입니다.

mAP 는 클래스별 AP 의 산술평균이라, 클래스 하나가 무너지면 전체 지표가
1/17(5.9%) 씩 직접 깎입니다. 소수 클래스는 학습도 안 되고 평가에서도 불리한
이중 불이익을 받습니다.

#### 네 가지로 대응했습니다

**① 많은 쪽은 덜 쓰되, "얼마나 덜 쓸지"를 형태 다양성으로 판단했습니다**

단순히 최소 클래스에 맞춰 자르면 데이터를 대부분 버리게 됩니다.
그래서 **카테고리마다 형태·색상이 얼마나 다양한지**를 기준으로 사용량을 달리했습니다.

| 성격 | 클래스 | 원천 보유 | 실제 사용 | 사용률 |
| --- | --- | --- | --- | --- |
| **형태가 다양함** | 유리병·비닐·의류·캔·페트병·나무·플라스틱·고철 | 33,539 ~ 47,411 | **12,000** | 25~36% |
| **형태가 일관됨** | 도기 | 44,809 | 6,500 | **15%** |
| | 형광등 | 38,093 | 5,200 | **14%** |
| | 박스류 | 25,327 | 5,000 | **20%** |
| | 책 | 17,396 | 3,300 | **19%** |
| | 스티로폼 | 42,869 | 3,500 | **8%** |

스티로폼은 4만 장이 있어도 대부분 흰색 직육면체라 3,500장이면 충분했습니다.
반면 고철은 같은 수량이라도 형태·색상 편차가 커서 12,000장을 다 썼습니다.

**"장수를 맞추는 것"이 아니라 "정보량을 맞추는 것"** 이 목표였습니다.

이 판단이 맞았다는 근거가 결과에 있습니다.

| 클래스 | 사용 장수 | mAP50-95 |
| --- | --- | --- |
| 스티로폼 | 3,481 (8%만 사용) | **0.9680** |
| 종이류/책 | 3,300 (19%만 사용) | **0.9762** |

**가장 적게 쓴 클래스가 가장 높은 성능**을 냈습니다.
장수가 아니라 다양성이 관건이라는 것을 보여줍니다.

**② 적은 쪽은 크롤링으로 직접 수집했습니다 (신문지)**

신문지는 원본이 136장뿐이라 어떤 샘플링으로도 해결되지 않았습니다.
그래서 웹 크롤링으로 직접 모았습니다. 파일명에 `crawl_` 접두사로 남아 있습니다.

**③ 크롤링 데이터는 전수 검토 후 선별했습니다**

크롤링 결과에는 신문지와 무관한 사진이 많이 섞여 있었습니다.
사람이 직접 확인해 학습에 쓸 만한 것만 남겼습니다.

파일 번호의 결번으로 확인됩니다.

```
clean   : 번호 0001~0435 중 250장 채택  → 채택률 57%
damaged : 번호 0479~0568 중  88장 채택  → 채택률 98%
```

**절반 가까이를 버렸습니다.** 자동 수집만 하고 검수를 건너뛰었다면
오히려 노이즈를 학습시킬 뻔했습니다.

**④ 그래도 부족한 만큼만 오프라인 증강했습니다**

| 클래스 | 고유 원본 | 증강본 | 최종 | 증강 비중 |
| --- | --- | --- | --- | --- |
| 신문지 | 442 (AI Hub 104 + 크롤링 338) | 1,294 | 1,736 | 75% |
| 종이 | 1,577 | 3,361 | 4,938 | 68% |
| 장난감 | 5,573 | 5,576 | 11,149 | 50% |
| 비철금속 | 6,190 | 5,613 | 11,803 | 48% |
| **나머지 13개** | 원본만 사용 | 0 | — | **0%** |

전체 학습 데이터의 **11%(15,844장)** 가 오프라인 증강본입니다.

**⑤ train/val 사이에서 부족분을 서로 보충했습니다**

train 이 부족하고 val 에 여유가 있으면 val 일부를 train 으로 돌렸고, 반대도 했습니다.
전처리에서 **SHA-1 교차 검사**로 누수를 막았습니다 — 실제로 10건이 걸려 val 쪽을 제거했습니다.

#### 결과

**349배 → 6.9배.** 최소 신문지 1,736장, 최대 유리병 11,978장입니다.

#### 검증해 보니 — 불균형 해소만으로는 부족했습니다

학습량과 성능의 상관을 계산했습니다.

```
스피어만 순위상관 (17개 클래스)
  전체        : +0.164
  신문지 제외  : -0.003   ← 사실상 무상관
```

**약한 상관마저 신문지 하나가 만든 것**이고, 나머지 16개에서는 데이터 양이
성능을 전혀 설명하지 못했습니다.

성능이 낮은 클래스는 **원인이 두 갈래**이고, 처방이 정반대입니다.

| 유형 | 클래스 | 고유 원본 | mAP | 처방 |
| --- | --- | --- | --- | --- |
| **다양성 부족** | 신문지 | 442 | 0.4396 | 추가 수집 |
| | 종이 | 1,577 | 0.7094 | 추가 수집 |
| **클래스 혼동** | 비철금속 | 6,190 | 0.6855 | 클래스 병합 또는 대분류 평가 |
| | 고철 | 10,924 | 0.7753 | 〃 |

고철과 비철금속은 **데이터가 충분한데도 낮습니다.** 혼동 행렬을 보면 서로를 헷갈립니다
(고철→비철금속 0.20, 비철금속→고철 0.28). 더 모아도 안 풀립니다.
다만 둘 다 대분류가 '고철류'로 같아 배출 방법이 동일하므로 **서비스상 오답은 아닙니다.**
대분류 기준으로는 둘 다 약 0.89 입니다.

#### 한 문장 요약

> 많은 쪽은 **형태 다양성 기준으로** 덜 쓰고, 적은 쪽은 **크롤링·검수·증강으로** 채워
> 349배를 6.9배까지 줄였습니다. 다만 남은 성능 병목은 데이터 양이 아니라
> **고유 다양성(신문지)과 클래스 정의(고철·비철금속)** 에 있었습니다.

### Q11-0. 그래서 불균형을 얼마나 개선한 건가요?

**지표에 따라 다릅니다. 그리고 그 차이가 이 프로젝트의 핵심 교훈입니다.**

| 지표 | ① 원천 보유 | ② 최종 학습 | ③ 고유 장면만 |
| --- | --- | --- | --- |
| 총량 | 519,857 | 144,315 | 128,471 |
| 최소 / 최대 | 136 / 47,411 | 1,736 / 11,978 | 442 / 11,978 |
| **최대÷최소** | **348.6배** | **6.9배** | **27.1배** |
| 지니계수 | 0.295 | **0.230** | 0.289 |
| 균등도(엔트로피) | 0.927 | 0.962 | 0.943 |
| 변동계수 | 0.546 | 0.433 | 0.522 |

**"349배 → 6.9배, 50배 개선"은 사실이지만 이것만 말하면 과장입니다.**

최대÷최소는 **양극단 두 클래스만** 보는 지표입니다. 원천 분포를 보면 상위 13개는
17,000~47,000으로 이미 꽤 고르고 하위 4개만 낮았습니다. 그래서 지니계수가 원래
0.295로 그리 높지 않았습니다. 분포 전체 기준으로는 **0.295 → 0.230, 22% 개선**입니다.

#### 가장 중요한 것은 ③번 열입니다

**증강본을 빼고 고유 장면만 세면 지니계수가 0.289 로 거의 개선되지 않았습니다.**

증강은 신문지를 442 → 1,736장으로 불렸지만 **서로 다른 장면은 442개 그대로**입니다.
명목상 불균형은 6.9배로 줄었어도, 모델이 실제로 배울 수 있는 정보량의 불균형은
**27.1배**로 남아 있습니다.

그리고 이 수치가 결과와 정확히 맞아떨어집니다. **신문지 mAP 는 0.4396** 입니다.
고유 다양성이 늘지 않았으니 성능도 오르지 않았습니다.

#### 세 문장 요약

1. **최소 클래스 절대량은 크게 개선** — 신문지 비중 0.026% → 1.203%(46배).
   이 중 실질 기여는 크롤링 7.5배이고, 증강은 장수만 늘렸습니다.
2. **분포 균등도는 완만하게 개선** — 지니 0.295 → 0.230 (22%).
3. **고유 다양성 불균형은 거의 그대로** — 27.1배. 증강이 메울 수 없는 부분이며,
   이것이 신문지 성능의 한계선이었습니다.

### Q11-1. 스티로폼은 4만 장이 있는데 3,500장만 썼다고요? 아깝지 않나요?

17개 중 두 번째로 높습니다.

거의 없습니다. 오히려 다수 클래스가 학습을 지배해 소수 클래스가 밀리는
부작용만 생깁니다.

**같은 GPU 시간을 다른 클래스에 쓰는 편이 전체 mAP 에 유리합니다.**
실제로 학습 시간이 20.3시간이었는데, 모든 클래스를 4만 장씩 썼다면
70만 장이 되어 100시간을 넘겼을 겁니다.

### Q11-2. 크롤링 데이터를 쓰면 원본 데이터셋과 분포가 달라지지 않나요?

**달라집니다. 이건 저희가 감수한 트레이드오프입니다.**

AI Hub 데이터는 통제된 환경에서 촬영됐지만, 크롤링 이미지는 조명·배경·해상도가
제각각입니다. 신문지 학습 데이터의 **76%(338/442)** 가 크롤링본이라 영향이 작지 않습니다.

다만 대안이 없었습니다. 136장으로는 어떤 기법으로도 학습이 되지 않습니다.
분포가 다른 데이터라도 **있는 편이 없는 것보다 낫다**고 판단했습니다.

오히려 실사용 사진은 통제된 환경이 아니므로, 크롤링 이미지가 실제 서비스 환경에
더 가까울 수도 있습니다. **다만 이건 검증하지 않은 가설입니다.**

한 가지 확실한 문제는 **검증 세트에는 크롤링 이미지를 넣지 않았다**는 점입니다.
신문지 val 16장은 전부 AI Hub 원본이라, 크롤링으로 학습한 모델을
원본 분포로만 평가한 셈입니다. 이건 설계 실수로 인정합니다.

# D. 증강

### Q12. mosaic이 왜 가장 효과적이었나요?

mosaic은 이미지 4장을 한 장면으로 합칩니다. 세 가지 효과가 있습니다.

1. 한 화면에 여러 물건이 있는 상황을 학습
2. 물건이 잘리거나 작게 보이는 경우를 학습
3. 배경 다양성 증가

실제 사용자가 찍는 사진(여러 물건이 섞인 분리수거함)과 조건이 비슷해서
효과가 있었다고 봅니다.

### Q13. motion blur는 왜 성능을 떨어뜨렸나요?

유일하게 음수(−0.0006)를 기록한 증강입니다.

화질을 일부러 떨어뜨리는 증강인데, 실제 사용자는 흐릿한 사진보다
**물건을 제대로 찍어서** 올립니다. 학습 데이터에만 있고 실제로는 드문 조건을
넣은 셈이라 도움이 되지 않았습니다.

다만 −0.0006은 **noise 범위 안**이라 "해롭다"기보다 "효과 없다"가 정확합니다.

### Q14. `close_mosaic`은 결국 무엇인가요?

`close_mosaic=N` 은 **마지막 N epoch 동안 mosaic을 끄는** 설정입니다.

mosaic으로 합성한 장면은 실제 이미지 분포와 다릅니다. 학습 막바지에 이걸 끄고
원본 분포로 마무리하면 성능이 올라갑니다.

저희는 처음에 이 의미를 몰라 `close_mosaic=10` + `epochs=10`으로 두었고,
그 결과 **전 구간에서 mosaic이 꺼진 채** 학습됐습니다.
서로 다른 4개 설정이 `0.807046`으로 똑같이 나온 게 이걸 발견한 단서였습니다.

최종 학습에서는 전체의 20%인 4 epoch로 설정했고, 그 구간에서
**0.8597 → 0.8637 (+0.0040)** 추가 상승을 확인했습니다.

### Q15. Optuna가 86클래스에서는 효과 있었는데 17클래스에서는 왜 실패했나요?

**데이터가 충분해지면 기본 설정이 이미 좋기 때문**이라고 봅니다.

86클래스일 때는 클래스당 89장으로 학습이 매우 불안정했고, 학습률·warmup 같은
설정이 수렴 여부를 좌우했습니다. 그래서 튜닝이 +0.14 만큼 기여했습니다.

17클래스로 재편한 뒤에는 클래스당 448장으로 학습이 안정적이었고,
Ultralytics의 `optimizer="auto"`가 데이터 규모를 보고 자동으로 정하는 값이
이미 충분히 좋았습니다.

**추가로, Optuna가 찾은 값은 7,623장 기준에 최적화된 값**입니다.
최종 학습은 144,315장으로 19배 규모라 그 값이 그대로 맞을 이유도 없었습니다.
`auto`는 데이터 규모에 맞춰 다시 계산하므로 이 점에서도 유리했습니다.
