# 사용자 시나리오

**버전** v1.0 · **기준일** 2026-09-28

페르소나 3명을 통해 분리쏙의 핵심 흐름(정상 분류, 지역 예외 규정, AI 보정+후속 질문)이 실제
사용 맥락에서 어떻게 동작하는지 정리합니다. 화면/API 매핑은 [06-user-flow.md](06-user-flow.md),
[10-api-specification.md](10-api-specification.md)를 참고하세요.

## 시나리오 1 — 자취 초년생의 "이거 뭐야?" 순간

### 페르소나: 김민준 (27세, 1인 가구, 서울 강남구 거주 3개월 차)

지방에서 상경해 처음 자취를 시작한 직장인. 본가에서는 부모님이 분리배출을 다 해주셔서 규칙을
제대로 배운 적이 없다. 스마트폰 사용에는 익숙하지만 지자체 분리배출 안내문은 읽어도 잘 이해가 안 된다.

### 시나리오

1. 민준은 택배로 온 스티로폼 박스와 완충재를 어떻게 버려야 할지 몰라 앱을 켠다.
2. 처음 쓰는 앱이라 회원가입(`POST /auth/signup`) 후 로그인한다. 로그인 응답의 `user.region`이
   `null`이라 자동으로 지역 선택 화면으로 이동한다.
3. "서울특별시 → 강남구"를 선택(`PATCH /users/me/region`)하고 홈 화면(촬영 화면)으로 진입한다.
4. 스티로폼 박스를 화면 중앙 가이드에 맞춰 촬영한다. 실시간 뷰파인더가 "인식됐어요"를 표시한 뒤
   촬영 버튼을 누른다.
5. `POST /analyze` 호출 — Vision AI가 중앙 객체를 스티로폼으로 탐지(`class_id=5`, `score=0.94`)하고,
   S3 업로드 + DB 저장이 완료된다.
6. 결과 화면에 "스티로폼류 · 스티로폼"과 강남구 기준 배출 요일, 그리고 RAG가 조회한 전국 공통
   배출 방법("테이프·운송장 제거 후 배출")이 함께 표시된다.
7. 민준은 "맞아요"를 눌러 확인한다(`POST /feedback/{id}/confirm`). 결과가 `is_correct=true`로 확정된다.
8. 다음에 또 헷갈릴 걸 알기에, 마이페이지에서 "스티로폼류"를 즐겨찾기에 추가해 둔다.

### 핵심 포인트
- 첫 사용자에게 지역 선택이 **강제 관문**으로 자연스럽게 안내됨(FR-203).
- AI 예측이 맞았을 때는 확인 한 번으로 흐름이 끝남 — 가장 짧고 빈번한 경로.

## 시나리오 2 — 이사한 다둥이 가정의 "우리 동네는 다르네?" 순간

### 페르소나: 박서연 (39세, 초등학생 자녀 둘, 최근 서울 → 경기도 화성시로 이사)

살림을 오래 해서 분리배출 자체는 익숙하지만, 이사 온 지 얼마 안 돼 새 동네의 예외 규정(경기도
일부 시·군은 전국 공통 규정과 다른 배출 방법을 쓴다)을 모른다. 아이들 간식 포장재 등 애매한
품목이 자주 나온다.

### 시나리오

1. 서연은 기존 계정으로 로그인한다. 이사 후 마이페이지에서 지역을 "서울특별시 강남구" →
   "경기도 화성시"로 변경한다(`PATCH /users/me/region`).
2. 요구르트병(유리병)을 촬영해 분석을 요청한다. `POST /analyze` 응답으로 `class_id=6`(유리병),
   `score=0.88`을 받는다.
3. 결과 화면에 전국 공통 배출 방법(`national_rule`)과 함께, **화성시 예외 규정**(`region_rule`)이
   함께 표시된다 — RAG 서비스가 사용자 지역이 경기도임을 확인하고 시·군별 예외 데이터를 추가로
   조회했기 때문이다.
4. 서연은 화면에 나온 안내만으로는 애매해서 채팅 아이콘을 눌러 "라벨은 떼야 하나요?"라고 물어본다.
5. `POST /chat` 호출 — RAG의 `/chat_node`가 방금 조회한 규정 텍스트를 근거로 "라벨과 뚜껑을 제거한
   뒤 배출해주세요" 같은 구체적인 답을 자연어로 생성해 돌려준다.
6. 답변에 만족한 서연은 "맞아요"로 분석을 확정한다.

### 핵심 포인트
- 지역이 서울에서 경기도로 바뀌면서 **지역 예외 규정(region_rule)** 이 처음으로 노출되는 경로.
- AI Agent 채팅이 규정을 "다시 검색"하지 않고 **방금 분석에 쓰인 컨텍스트를 재사용**해 답한다.
- 채팅은 Stateless라, 서연이 앱을 나갔다 들어와도 이 대화는 남지 않는다(재질문 시 매번 새로 생성).

## 시나리오 3 — 시니어 사용자의 "AI가 틀린 것 같아요" 순간

### 페르소나: 이정자 (68세, 은퇴 후 손주 돌봄, 경기도 수원시 거주)

스마트폰은 메신저와 사진 촬영 정도만 능숙하게 다룬다. 복잡한 메뉴보다는 큰 버튼과 단순한 확인
절차를 선호한다. 폐형광등처럼 깨지기 쉬운 품목을 다룰 때 특히 조심스럽다.

### 시나리오

1. 정자는 다 쓴 형광등을 촬영한다. 그런데 조명 반사 때문에 AI가 이를 "유리병"(`class_id=6`,
   `score=0.61`)으로 잘못 예측한다.
2. 결과 화면에 "유리병"이 뜨지만, 정자는 이게 형광등이라는 걸 안다. "다른 후보 선택"을 눌러
   하단 시트를 연다.
3. Top-K 후보 목록에 "형광등"이 보여서 바로 선택한다(`POST /feedback/{id}/select-candidate`,
   `class_id=16`). `final_class_id=16`, `correction_source="USER"`로 저장된다.
4. 만약 후보 목록에도 형광등이 없었다면, 정자는 "여기 없어요"를 눌렀을 것이다 — 이 경우
   `POST /feedback/{id}/not-in-list`가 호출되어 RAG 서비스의 재분류 그래프(Gemini Vision 재분류)가
   원본 이미지를 다시 분석한다. 화면에는 "AI가 다시 살펴보고 있어요" 심층 분석 화면이 표시된다.
5. 정자통은 결과 화면에서 "깨지지 않게 감싸서 배출"이라는 안내를 보고, 확실히 하기 위해 채팅으로
   "전구도 같이 버려도 되나요?"라고 물어본다. AI Agent가 "전구는 별도로 배출해주세요"라고 답한다.

### 핵심 포인트
- AI가 틀렸을 때 **후보 재선택**과 **재분석 요청** 두 가지 보정 경로가 모두 존재함(FR-402, FR-403).
- 재분석이 유효한 답을 못 찾으면 "재촬영 안내"로 이어지는 안전장치가 있음(FR-405, `AI_RECLASSIFY_FAILED`).
- 조작이 단순한 3단계(촬영 → 확인/보정 → 완료)로 시니어 사용자도 큰 어려움 없이 완료 가능.
